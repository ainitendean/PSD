Ekstraksi Fitur Time Series Polutan Udara dengan TSFEL pada Data Polutan Kecamatan Tikala, Manado#

Notebook ini merupakan kelanjutan dari notebook Analisis Data Polutan Udara di Wilayah Kecamatan Tikala Kabupaten Manado, yang sudah membahas Business Understanding dan Data Understanding termasuk proses pengambilan data dari Sentinel-5P. Fokus notebook ini adalah tahap ekstraksi fitur dari data CO, NO2, dan SO2 memakai pustaka TSFEL, dimulai dari pollutant_data_tikala.csv yang sudah dihasilkan sebelumnya.

TSFEL (Time Series Feature Extraction Library) membantu mengubah data deret waktu mensehingga kumpulan angka ringkas yang disebut fitur. Tiap fitur menangkap satu ciri khas dari sinyal, bisa berupa seberapa tinggi rata-ratanya, seberapa liar fluktuasinya, atau frekuensi mana yang paling menonjol di dalamnya.

Data mentah polutan tercatat sebagai ratusan nilai harian yang naik turun sepanjang tahun, sehingtidak repot kalau mau dibandingkan langsung antarwilayah. Lewat ekstraksi fitur, satu tahun pola data itu dipadatkan sehingga satu baris angka per wilayah, sehingga bisa diperlakukan sebagai data tabular biasa dan lebih siap digunakan untuk tahap analisis berikutnya seperti clustering.

TSFEL membagi 68 fitur yang tersedia ke dalam empat domain:

  • Statistical, memelihat karakteristik distribusi nilai sinyal (mean, standar deviasi, skewness, dan sejenisnya), tanpa peduli urutan waktunya

  • Temporal, memelihat pola perubahan sinyal sepanjang waktu (kemiringan tren, jumlah titik balik, dan lainnya)

  • Spectral, mengubah sinyal ke domain frekuensi lewat FFT atau wavelet, baru diukur karakteristiknya di sana

  • Fractal, mengukur kompleksitas dan pola “memori jangka panjang” pada sinyal

Ekstraksi pada notebook ini dilakukan terpisah untuk titidak polutan (CO, NO2, SO2), masing-masing menghasilkan 68 fitur.

1.2 interq_range(signal) — Interquartile Range (IQR)#

Kategori: Statistik

Intinya apa? IQR itu cara mengukur “seberapa lebar” separuh data yang ada di tengah-tengah, setelah data diurutkan dari kecil ke besar. Kita potong 25% data paling kecil dan 25% data paling besar, terus lihat seberapa jauh jarak antara batas-batasnya.

Bedanya dengan standar deviasi:

  • Standar deviasi → ngukur sebaran dari titik rata-rata, dan gampang keganggu kalau ada data yang aneh/ekstrem (outlier).

  • IQR → cuma lihat posisi data setelah diurutkan, jadi outlier di ujung-ujung nggak terlalu ngaruh.

Prinsip ini juga dipakai buat deteksi outlier di boxplot, lewat batas whisker: \(Q_1 - 1{,}5 \times IQR\) dan \(Q_3 + 1{,}5 \times IQR\).

Kalau dipakai buat sinyal polutan: IQR nunjukin seberapa stabil kadar suatu polutan di luar hari-hari ekstrem.

  • IQR kecil → sebagian besar hari kadarnya mirip-mirip (stabil).

  • IQR besar → kadarnya naik-turun cukup jauh dari hari ke hari.

Dua istilah kunci:

  • Q1 (kuartil bawah): titik di mana 25% data terkecil ada di bawahnya.

  • Q3 (kuartil atas): titik di mana 75% data terkecil ada di bawahnya (atau 25% data terbesar ada di atasnya).

Rumus: $\( IQR = Q_3 - Q_1 \)$

Q1 dan Q3 dicari dari data yang sudah diurutkan, pakai metode interpolasi linear (ini metode default di TSFEL maupun NumPy): $\( \text{posisi} = (n-1) \times p, \quad p = 0{,}25 \text{ untuk } Q_1,\ p = 0{,}75 \text{ untuk } Q_3 \)$

Contoh perhitungan, langkah demi langkah

Data contoh (sudah diurutkan, \(n = 8\)):

index:  0  1  2  3  4  5  6  7
nilai:  2  4  4  4  5  5  7  9

Langkah 1 Cari Q1

Posisinya dulu: $\( \text{posisi}_{25} = (8-1) \times 0{,}25 = 1{,}75 \)$

Posisi 1,75 artinya: nggak tepat di satu index, tapi ada di antara index 1 dan index 2 — sudah “jalan” 75% dari index 1 menuju index 2.

Nilai di index 1 dan 2 sama-sama 4, jadi: $\( Q_1 = 4 + 0{,}75 \times (4 - 4) = 4{,}0 \)$

Langkah 2 Cari Q3

Posisinya: $\( \text{posisi}_{75} = (8-1) \times 0{,}75 = 5{,}25 \)$

Posisi 5,25 ada di antara index 5 (nilai 5) dan index 6 (nilai 7), sudah jalan 25% dari index 5 menuju index 6: $\( Q_3 = 5 + 0{,}25 \times (7 - 5) = 5{,}5 \)$

Langkah 3 Hitung IQR

\[ IQR = Q_3 - Q_1 = 5{,}5 - 4{,}0 = \mathbf{1{,}5} \]
# Contoh perhitungan IQR secara manual tanpa fungsi percentile atau fungsi fitur TSFEL
x_contoh = [2, 4, 4, 4, 5, 5, 7, 9]

# Mengurutkan data secara manual dengan bubble sort
x_urut = x_contoh[:]
for i in range(len(x_urut)):
    for j in range(0, len(x_urut) - i - 1):
        if x_urut[j] > x_urut[j + 1]:
            sementara = x_urut[j]
            x_urut[j] = x_urut[j + 1]
            x_urut[j + 1] = sementara

n = len(x_urut)

# Posisi kuartil mengikuti rumus (n-1) x p
pos_q1 = (n - 1) * 0.25
pos_q3 = (n - 1) * 0.75

# Interpolasi linear manual untuk Q1
idx_q1 = int(pos_q1)
pecahan_q1 = pos_q1 - idx_q1
q1 = x_urut[idx_q1] + pecahan_q1 * (x_urut[idx_q1 + 1] - x_urut[idx_q1])

# Interpolasi linear manual untuk Q3
idx_q3 = int(pos_q3)
pecahan_q3 = pos_q3 - idx_q3
q3 = x_urut[idx_q3] + pecahan_q3 * (x_urut[idx_q3 + 1] - x_urut[idx_q3])

iqr_manual = q3 - q1

print("Data terurut:", x_urut)
print(f"Posisi Q1 = {pos_q1}, Q1 = {q1}")
print(f"Posisi Q3 = {pos_q3}, Q3 = {q3}")
print(f"IQR = Q3 - Q1 = {iqr_manual}")

Data terurut: [2, 4, 4, 4, 5, 5, 7, 9]
Posisi Q1 = 1.75, Q1 = 4.0
Posisi Q3 = 5.25, Q3 = 5.5
IQR = Q3 - Q1 = 1.5

Penjelasan kode:

  • data contoh disimpan sebagai list Python sederhana, tanpa numpy.percentile dan tanpa fungsi interq_range dari TSFEL

  • data diurutkan secara manual menggunakan bubble sort agar proses pengurutan dapat dimelihat secara eksplisit

  • posisi Q1 dan Q3 dihitung menggunakan rumus (n-1) × p

  • nilai Q1 dan Q3 diperoleh dengan interpolasi linear secara manual berdasarkan posisi desimalnya

  • nilai interq_range kemudian dihitung langsung dengan rumus Q3 - Q1

  • tidak ada fungsi statistik bawaan yang digunakan untuk menghitung hasil IQR

1.3 human_range_energy(signal, fs) — Human Range Energy (HRE)#

Kategori: Spektral (frekuensi)

Fitur ini awalnya dibuat untuk menganalisis sinyal gerak tubuh manusia, misalnya data accelerometer dari HP atau smartwatch. Tujuannya adalah mengukur seberapa besar porsi energi sinyal yang berada pada rentang frekuensi 0,6 sampai 2,5 Hz. Rentang ini biasanya berkaitan dengan aktivitas fisik seperti langkah kaki atau detak jantung.

Cara kerjanya begini. Sinyal yang tadinya berada dalam domain waktu diubah dulu ke domain frekuensi menggunakan FFT (Fast Fourier Transform). Setelah itu kita bisa tahu berapa besar energi sinyal pada setiap frekuensi. Energi yang jatuh pada rentang 0,6 sampai 2,5 Hz kemudian dijumlahkan, lalu dibandingkan dengan energi total di seluruh spektrum. Hasilnya adalah sebuah rasio antara 0 dan 1. Semakin besar porsi energi yang ada di rentang tersebut, semakin besar pula nilai HRE-nya.

Ada satu hal penting untuk kasus data polutan. Fitur ini dirancang untuk sinyal berfrekuensi tinggi, dalam skala sub detik seperti gerak tubuh manusia. Kalau fitur ini diterapkan pada data polutan harian, yang hanya punya satu sampel per hari dan jauh lebih lambat dari 0,6 Hz, hasilnya kemungkinan besar akan selalu bernilai 0. Ini bukan berarti ada kesalahan pada data. Itu memang konsekuensi wajar karena skala waktu datanya sangat berbeda dari konteks asal fitur ini, yaitu gerak manusia yang cepat, dibandingkan dengan konsentrasi polutan yang berubah pelan dari hari ke hari.

Rumusnya sebagai berikut.

\[ HRE = \frac{\displaystyle\sum_{0.6 \le f \le 2.5} |X(f)|^2}{\displaystyle\sum_{f} |X(f)|^2}, \quad X(f) = \text{FFT}(x) \]

Bagian pembilang adalah jumlah energi pada rentang 0,6 sampai 2,5 Hz. Bagian penyebut adalah jumlah energi di seluruh frekuensi, atau total energi sinyal secara keseluruhan.

Contoh perhitungan manual, langkah demi langkah

Sinyal contoh yang digunakan adalah gabungan dua gelombang sinus, dengan frekuensi sampling 10 Hz atau 10 sampel per detik, durasi 20 detik, sehingga totalnya ada 200 sampel.

\[ x(t) = \sin(2\pi \cdot 1{,}0 \cdot t) + 0{,}5 \sin(2\pi \cdot 4{,}0 \cdot t) \]

Sinyal ini merupakan campuran gelombang berfrekuensi 1 Hz dan gelombang berfrekuensi 4 Hz dengan amplitudo yang lebih kecil.

Langkah pertama adalah mencari resolusi frekuensi dari FFT. Resolusi ini menentukan seberapa detail FFT bisa membedakan antar frekuensi.

\[ \Delta f = \frac{f_s}{n} = \frac{10}{200} = 0{,}05 \text{ Hz} \]

Langkah kedua adalah menghitung energi, atau PSD, pada setiap frekuensi lewat FFT. Karena sinyal ini hanya merupakan gabungan dua gelombang sinus murni, hampir seluruh energinya terkumpul pada dua titik frekuensi saja. Pada frekuensi 1,0 Hz, yang merupakan komponen utama, energinya sekitar 10.000. Pada frekuensi 4,0 Hz, yang merupakan komponen kedua, energinya sekitar 2.500. Total energi di seluruh spektrum adalah 12.500.

Langkah ketiga adalah menjumlahkan energi yang masuk ke rentang 0,6 sampai 2,5 Hz. Frekuensi 1,0 Hz masuk ke dalam rentang tersebut, sedangkan frekuensi 4,0 Hz berada di luar rentang karena sudah melebihi 2,5 Hz. Jadi hanya energi pada frekuensi 1,0 Hz yang dihitung.

\[ \sum_{0.6\le f\le 2.5} |X(f)|^2 = 10.000 \]

Langkah keempat adalah menghitung rasio HRE.

\[ HRE = \frac{10.000}{12.500} = \mathbf{0{,}8} \]

Artinya sekitar 80 persen dari total energi sinyal ini berada pada rentang frekuensi yang dikaitkan dengan gerak manusia, yaitu 0,6 sampai 2,5 Hz. Ini masuk akal karena komponen utama sinyalnya, yaitu 1 Hz, memang berada di dalam rentang tersebut.

Catatan tambahan: hasil perhitungan manual ini nantinya akan dicocokkan kembali dengan hasil fungsi TSFEL pada bagian kode berikutnya.

# Contoh verifikasi human_range_energy secara manual

if energi_dalam_rentang == 0:
    hre_manual = 0
    print("Seluruh rentang 0,6-2,5 Hz berada di atas Nyquist.")

Penjelasan kode:

  • verifikasi dilakukan tanpa np.fft, np.abs, atau fungsi human_range_energy dari TSFEL

  • frekuensi Nyquist dihitung langsung dengan rumus fs / 2

  • karena fs = 10 Hz, frekuensi maksimum yang dapat direpresentasikan adalah 5 Hz, sehingtidak rentang 0,6–2,5 Hz memang masih dapat direpresentasikan pada contoh ini

  • contoh ini hanya menunjukkan pemeriksaan batas frekuensi secara manual; perhitungan rasio energi lengkap digunakan pada data riil apabila terdapat komponen frekuensi di dalam rentang tersebut

1.4 Verifikasi Manual interq_range dan human_range_energy pada Data Asli#

Verifikasi berikut menggunakan data riil CO, NO2, dan SO2 dari pollutant_data_tikala.csv. Perhitungan enam hasil dilakukan kembali secara manual, bukan dengan mengmengambil nilai dari hasil ekstraksi TSFEL.

Untuk interq_range, data diurutkan secara manual, posisi Q1 dan Q3 dihitung menggunakan rumus interpolasi, lalu IQR dihitung sebagai Q3 - Q1.

Untuk human_range_energy, data polutan memiliki satu pengamatan per hari sehingtidak fs = 1 Hz. Frekuensi Nyquist adalah 0,5 Hz, sedangkan rentang fitur adalah 0,6–2,5 Hz. Karena seluruh rentang fitur berada di atas Nyquist, energi pada rentang tersebut secara matematis adalah 0 sehingtidak HRE = 0.

import numpy as np
from scipy import signal

# BAGIAN 1: FUNGSI PERHITUNGAN MANUAL

def urut_manual(data):
    """Mengurutkan data menggunakan Bubble Sort"""
    hasil = data[:]

    for i in range(len(hasil)):
        for j in range(0, len(hasil) - i - 1):
            if hasil[j] > hasil[j + 1]:
                sementara = hasil[j]
                hasil[j] = hasil[j + 1]
                hasil[j + 1] = sementara

    return hasil


def kuartil_manual(data_urut, p):
    """Menghitung kuartil dengan interpolasi linear secara manual"""
    n = len(data_urut)
    posisi = (n - 1) * p
    indeks = int(posisi)
    pecahan = posisi - indeks

    if indeks + 1 < n:
        return (
            data_urut[indeks]
            + pecahan * (data_urut[indeks + 1] - data_urut[indeks])
        )

    return data_urut[indeks]

2. Data Preparation: Deteksi Outlier dan Imputasi Missing Value (Dua Skenario Interpolasi)#

Sebelum sinyal CO, NO2, dan SO2 masuk ke ekstraksi fitur, keduanya dibersihkan dulu dari outlier dan nilai kosong. Bedanya dari notebook sebelumnya, pembersihan di sini dilakukan dengan dua metode interpolasi berbeda, yaitu linear dan polinomial, sehingga nantinya ada dua versi sinyal bersih untuk tiap polutan.

Deteksi outlier memakai metode IQR, caranya sama untuk kedua skenario. Yang membedakan cuma cara mengisi nilai kosongnya:

  1. Skenario linear memakai interpolate(method="time"), yaitu mengisi nilai kosong dengan garis lurus antar titik yang ada, dihitung berdasarkan jarak tanggal asli.

  2. Skenario polinomial memakai interpolate(method="polynomial", order=2), yaitu mengisi nilai kosong mengikuti kurva lengkung derajat dua, bukan garis lurus.

Kedua metode sama-sama ditutup dengan ffill() dan bfill() untuk mengisi nilai kosong yang tersisa di awal atau akhir data.

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt

POLUTAN_TARGET = ["NO2", "SO2", "CO"]
ORDE_POLINOMIAL = 2

df = pd.read_csv("pollutant_data_tikala.csv")
df["date"] = pd.to_datetime(df["date"])
df = df.sort_values("date").reset_index(drop=True)

# Menyimpan data asli sebelum proses penanganan
df_awal = df.copy()

# Rentang tanggal penuh satu tahun, dipakai supaya kedua skenario
# (linear dan polinomial) punya panjang baris yang sama, 366 hari,
# termasuk tanggal yang barisnya hilang total di data mentah
rentang_penuh = pd.date_range(df_awal["date"].min(), df_awal["date"].max(), freq="D")

sinyal_bersih = {"linear": {}, "polynomial": {}}
ringkasan_missing_list = []
batas_iqr = {}
outliers_iqr_dict = {}

for pol in POLUTAN_TARGET:
    df[pol] = pd.to_numeric(df[pol], errors="coerce")

    n_missing_awal = df[pol].isna().sum()
    persen_missing_awal = (n_missing_awal / len(df)) * 100

    q1, q3 = df[pol].quantile([0.25, 0.75])
    iqr = q3 - q1
    lower = q1 - 1.5 * iqr
    upper = q3 + 1.5 * iqr

    kondisi_outlier = (df[pol] < lower) | (df[pol] > upper)
    outliers_iqr_dict[pol] = df.loc[kondisi_outlier, ["date", pol]].copy()
    jumlah_outlier = kondisi_outlier.sum()
    batas_iqr[pol] = {"lower": lower, "upper": upper}

    df.loc[kondisi_outlier, pol] = np.nan
    n_missing_setelah_outlier = df[pol].isna().sum()
    persen_missing_setelah_outlier = (n_missing_setelah_outlier / len(df)) * 100

    # ---------- Skenario linear ----------
    hasil_linear = (
        df.set_index("date")[[pol]]
        .reindex(rentang_penuh)
        .interpolate(method="time")
        .ffill()
        .bfill()
    )
    sinyal_bersih["linear"][pol] = hasil_linear[pol]

    # ---------- Skenario polinomial ----------
    lengkap = df.set_index("date")[[pol]].asfreq("D")
    tmp = lengkap.reset_index()
    tmp[pol] = tmp[pol].interpolate(method="polynomial", order=ORDE_POLINOMIAL)
    tmp[pol] = tmp[pol].ffill().bfill()
    hasil_poly = tmp.set_index("date")
    sinyal_bersih["polynomial"][pol] = hasil_poly[pol]

    ringkasan_missing_list.append({
        "polutan": pol,
        "missing_awal": n_missing_awal,
        "persen_missing_awal": round(persen_missing_awal, 2),
        "jumlah_outlier": int(jumlah_outlier),
        "missing_setelah_outlier": n_missing_setelah_outlier,
        "missing_sesudah_linear": int(sinyal_bersih["linear"][pol].isna().sum()),
        "missing_sesudah_polynomial": int(sinyal_bersih["polynomial"][pol].isna().sum()),
    })

Penjelasan kode:

  1. rentang_penuh dibuat lebih dulu, berisi semua tanggal dari awal sampai akhir data tanpa ada yang bolong, 366 hari. Ini dipakai supaya kedua skenario sama-sama lengkap 366 baris, termasuk 3 tanggal yang barisnya hilang total di data mentah.

  2. Skenario linear memakai reindex(rentang_penuh) lebih dulu sebelum interpolate(method="time"), supaya tanggal yang hilang total ikut muncul sebagai baris kosong, baru diisi berdasarkan jarak tanggal asli.

  3. Skenario polinomial memakai asfreq("D") dengan tujuan yang sama, yaitu melengkapi tanggal yang hilang total, baru sesudah itu index direset ke angka biasa karena interpolate(method="polynomial") butuh index numerik, bukan index waktu.

  4. sinyal_bersih sekarang berbentuk dictionary dua tingkat, kunci pertama nama skenario (linear atau polynomial), kunci kedua nama polutan, dan keduanya konsisten sama-sama berisi 366 nilai.

def to_scalar(result):
    if isinstance(result, dict) and "values" in result:
        result = result["values"]
    if isinstance(result, (list, tuple, np.ndarray)):
        arr = np.asarray(result, dtype=float)
        return float(np.nanmean(arr))
    return float(result)

def extract_one(fn_name, signal, fs):
    fn = getattr(tsfel_features, fn_name)
    params = inspect.signature(fn).parameters
    if "fs" in params:
        result = fn(signal, fs)
    else:
        result = fn(signal)
    return to_scalar(result)

4.3 Grafik Perbandingan Fitur Statistik Dasar, Linear vs Polinomial#

Membandingkan beberapa fitur statistik dasar (calc_mean, calc_std, skewness, kurtosis) antara skenario linear dan polinomial, untuk tiap polutan, supaya terlihat seberapa besar pengaruh metode interpolasi terhadap nilai fiturnya.

fitur_pembanding = ["calc_mean", "calc_std", "skewness", "kurtosis"]

fig, axes = plt.subplots(1, len(fitur_pembanding), figsize=(18, 4))

for ax, fitur in zip(axes, fitur_pembanding):
    nilai_linear = [extracted_linear[f"{pol}_{fitur}"].values[0] for pol in POLUTAN_TARGET]
    nilai_poly = [extracted_poly[f"{pol}_{fitur}"].values[0] for pol in POLUTAN_TARGET]

    x = np.arange(len(POLUTAN_TARGET))
    lebar = 0.35

    ax.bar(x - lebar/2, nilai_linear, width=lebar, label="Linear", color="tab:blue")
    ax.bar(x + lebar/2, nilai_poly, width=lebar, label="Polinomial", color="tab:orange")
    ax.set_xticks(x)
    ax.set_xticklabels(POLUTAN_TARGET)
    ax.set_title(fitur)
    ax.grid(alpha=0.3)

axes[0].legend()
plt.suptitle("Perbandingan Fitur Statistik Dasar, Linear vs Polinomial (Kecamatan Tikala)")
plt.tight_layout()
plt.show()

Penjelasan kode:

  1. Tiap subplot menampilkan satu fitur pembanding, dengan dua batang berdampingan untuk tiap polutan, satu mewakili skenario linear dan satu mewakili skenario polinomial.

  2. Kalau kedua batang hampir sama tinggi, berarti metode interpolasi tidak banyak mengubah karakter sinyalnya. Kalau beda jauh, berarti pemilihan metode interpolasi cukup berpengaruh terhadap fitur itu.
